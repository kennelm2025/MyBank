Framework / Reference

How the simulator's data sets fit together, and how strategic lenses turn evidence into a defensible decision.

1 · Data sets

The simulator carries ten data sets organised in three layers. Each has a single, well-defined purpose. The eval team interacts with them at different altitudes: L1 is evidence, the Seat layer is board context, and L2 is the strategic lens applied to evidence.

This is how an abstract board-level question ("can the bank influence this vendor when it needs to?") becomes a calculable score from concrete evidence. 3 · How L2-D2 weights turn L1 evidence into a strategic decision

There is one mechanism. It runs the same way whether the L2-D2 input represents raw evidence (every weight = 5), stated direction (presets at neutral bias), or an edge case (presets at active bias). Only L2-D2 changes; the math is identical. L2-D2 weights are preference coefficients applied at the L1-to-L2 roll-up — L1 data itself is never modified.

StepWhat happensFormula / mechanism
1Seat answers L2-D2 — each seat sets per-SQ weight 1-10 (neutral = 5). Their preset priorities define the natural pattern; their EC bias amplifies or dampens that voice.seat_SQ_weight = preset[SQ] × (bias / 5)
2Aggregate to board view — the 8 seats' L2-D2 answers blend via meta-weights into one board-level SQ weight per question.board_SQ_weight = Σ over seats (meta[seat] × seat_SQ_weight)
3L1-level coefficient — for each L1, sum contributions from every SQ that references it. Neutral state (every weight = 5) collapses to zero contribution.L1_coef = Σ over referencing SQs of (board_SQ_weight − 5) × evidence_weight
4L1 weight in roll-up — combine question-count baseline with the lens coefficient. At neutral, this collapses to the raw dim-weighted score.L1_weight = qCount(L1) × (5 + L1_coef)
5Dimension L2 score — per-vendor weighted average of L1-D4 scores within each dim, using L1 weights from step 4.L2_dim[v] = Σ (L1_weight × L1_score[v]) / Σ L1_weight
6L2-D3 overall — dim-weighted average across 6 dims (D1 25% / D2 20% / D3 15% / D4 15% / D5 15% / D6 10%). Display-flipped at render.L2-D3[v] = 6 − Σ dim_weight × L2_dim[v]
Two invariants this preserves.
(i) Neutral collapse: if every SQ weight is at 5 (no bias), L2-D3 ranking is mathematically identical to L1 ranking. Zero bias = no lens.
(ii) L1 data is canonical: never modified. The lens only changes the weight each L1 carries in the L2 roll-up. Same coefficient applied to every vendor — the relative position stays fair.

Reading an edge case. Each EC's panel on the Weights tab shows seat biases for that scenario, the client-facing recommendation narrative (the headline argument anchored in CEO imperatives), the technical worldview details, the SQs amplified, the board challenge, and the changeMind — a pre-committed falsification test that says "if evidence X comes back, this EC collapses." That changeMind is the eval team's most powerful asset: a decision rule written before the data lands, harder to rationalise away later.

5 · How the data layers combine into an actual decision

If the raw L1 data is very decisive, the L2 strategic lens is likely muted — the evidence already decided and the board is endorsing what the data says. If the decision at L1 is close, the strategic direction and bias of the executive steps in and makes the decision. This is where L2 does its real work — putting weight on what should matter, given the bank's strategic intent, and seeing how that reshapes a close-tied result.

The edge cases are meant to help that strategic decision-making and to refine the model. Each EC tells a story aligned to the key strategic question that has the most impact on the final decision under that worldview. Each one shows examples of L1 data that supports the narrative. The narrative is a view of the merged seat positions on at least one strategic question — what the room sounds like when this worldview leads the conversation.

The recommendation that emerges is whichever EC: (a) the board can defend strategically, (b) the evidence supports, and (c) survives the changeMind test. Anything else is either an unargued recommendation or an unfalsifiable one. Both are weak. The simulator is built so the eval team can never accidentally produce either.

6 · The simulator never goes away

Even after all three vendor scorecards are imported, D2-Simulator continues to run alongside D2-Vendor. This gives the eval team a rehearsal-versus-reality diagnostic.

The audit log (downloadable CSV from the Import Status panel) records every score swap with disposition codes (OK, BLANK, TEXT_MATCHED, OUT_OF_RANGE) so the eval team can trace exactly which question got which score from which source.
